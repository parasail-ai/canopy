Under the hood

Routing happens per step, not per task.

01 · The agent sends step n

A coding agent is a loop: it asks for a completion, runs the tool calls it gets back, and sends the results in with the next request. Canopy sits on that request. Every message already carries the previous step's tool output, so there is nothing extra to integrate.

02 · The decision model picks a tier

Before generating anything, a small model looks at the request: how deep the trajectory is, whether tests are red, whether someone is waiting on the result. It decides two things at once — which model, and which silicon to run it on. Most steps go to an open model on cost-optimized hardware; latency-sensitive ones move to fast hardware. The decision costs a fraction of a cent.

03 · The judge reads the tool results

When the results of that step come back on the next request, a judge grades them: did the tests move, did the edit apply, is the agent going in circles? A pass means the loop continues. A fail means the step is re-routed to a smarter tier and the better completion replaces the one the agent would have acted on next.
